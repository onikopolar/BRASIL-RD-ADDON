PONTO CENTRAL: magnetHelper.ts
-------------------------------
Arquivo: src/lib/magnetHelper.ts
Unica fonte de verdade para parse de magnet links no sistema.

Exports:
  analisarMagnet(magnet: string) -> Promise<DadosMagnet | null>
    - Usa parse-torrent (biblioteca ESM, carregada via dynamic import)
    - Retorna: { infoHash, nome, anuncios }
    - infoHash: hex 40 caracteres, lowercase
    - nome: parametro "dn" do magnet (nome canonico do torrent)
    - anuncios: trackers (parametro "tr")
    - Retorna null se magnet invalido ou parse falhar

  gerarUrlResolve(magnet, chaveApi, nomeArquivo, indiceArquivo, tipo, temporada, episodio) -> Promise<string>
    - Chama analisarMagnet() internamente
    - Monta URL: /resolve/torbox/{apiKey}/{infoHash}/null/{fileIdx}/{filename}?type=...&season=...&episode=...

O que NAO EXISTE mais:
  - extractHashFromMagnet (removido)
  - extrairInfoHash (removido)
  - generateLazyResolveUrl (substituido por gerarUrlResolve)
  - generateOldLazyResolveUrl (removido)
  - base32ParaHex (removido — parse-torrent faz internamente)
  - Qualquer regex de extracao de infoHash (zero regex proprio)

========================================================================
FASE 1: DESCOBERTA DE MAGNETS (SCRAPING)
========================================================================

1. Stremio cliente faz GET /torbox={apiKey}/stream/series/tt7631058:2:6.json

2. StreamHandler.handleStreamRequest()
   -> Busca no banco de dados (getStreamsFromDatabase)
   -> Busca no catalogProvider (getStreamsFromCatalog)
   -> (Torrentio fallback BLOQUEADO)

3. CatalogProvider.performIntelligentScraping()
   -> TorrentScraperService.searchTorrents()
      -> TorrentIndexer API (retorna magnet_link)
      -> WordPress scrapers (BLUDV, Comando, StarckFilmes)
   -> Retorna ScrapedTorrent[] (title, magnet, seeders, size, quality, provider, language)

4. CatalogProvider.deduplicateTorrentsByMagnet()
   -> Para cada torrent: await analisarMagnet(t.magnet)
   -> Extrai infoHash via parse-torrent
   -> Remove duplicados por infoHash

========================================================================
FASE 2: VALIDACAO E FILTRAGEM
========================================================================

5. CatalogProvider.filterAndValidateTorrents()
   a. Pre-filtro: torrents.filter(t => TitleFilter.conteudoEmPortugues(t.title))
      -> Descarta torrents sem indicadores PT-BR

   b. Para cada torrent PT: await analisarMagnet(t.magnet)
      -> Extrai nome canonico do magnet (parametro "dn")

   c. TitleFilter.titulosCombinam(tituloParaValidar, imdbId, season, episode)
      -> tituloParaValidar = nomeCanonico || t.title
      -> Nome canonico do parse-torrent tem PRIORIDADE sobre titulo do scraper
      -> TitleFilter valida: temporada, episodio, similaridade de titulo

   d. Fallback: se season && titulo contem "temporada completa" -> aceita

   Resultado: { valid: ScrapedTorrent[], invalid: ScrapedTorrent[] }

========================================================================
FASE 3: CRIACAO DE STREAMS
========================================================================

6. CatalogProvider.processTorrentsWithOptimization()
   -> streamFormatter.createMultipleQualityStreams(torrent, request, ...)
      -> Extrai qualidades do titulo (2160p, 1080p, 720p, HD)
      -> Para cada qualidade:

         a. Stream DIRETO (se linkDireto disponivel):
            criarStreamDireto()
            -> await analisarMagnet(linkDireto)
            -> stream.infoHash = dados.infoHash
            -> stream.url = linkDireto (CDN)

         b. Stream LAZY (magnet, sem cache RD):
            criarStreamLazy()
            -> await analisarMagnet(magnet)
            -> magnetHash = dados.infoHash
            -> await gerarUrlResolve(magnet, apiKey, filename, fileIdx, tipo, season, episode)
            -> stream.url = URL lazy gerada
            -> stream.infoHash = magnetHash (se nao tiver url)

   Stream object: { title, name, infoHash?, url?, fileIdx }

7. Retorna JSON para Stremio cliente com array de streams

========================================================================
FASE 4: RESOLUCAO (QUANDO USUARIO CLICA PLAY)
========================================================================

8. Stremio chama GET /resolve/torbox/{apiKey}/{infoHash}/null/{fileIdx}/{filename}
   Query params: ?type=series&season=2&episode=6

9. resolveRoutes.ts
   -> extrairInfoHashDoMagnet(magnet) -> await analisarMagnet(magnet)
   -> processMagnetWithTorbox(magnet, apiKey, season, episode, type)

   a. RdTorrentCacheService.getTorrentId(magnetHash, apiKey, torboxService)
      -> Cache (AdvancedCacheService + Map)
      -> MISS -> torboxService.findExistingTorrent(magnetHash, apiKey)
         -> GET /torrents/mylist -> busca por hash match
         -> extrairMagnetHash() -> await analisarMagnet(link)

   b. Se encontrado: getStreamLink(torrentId, apiKey, season, episode)
      -> torboxService.getStreamLinkForTorrent(torrentId, apiKey, season, episode)
         -> GET /torrents/mylist?id=X
         -> Itera arquivos, extrai temporada/episodio via EpisodeMatcher
         -> Seleciona melhor arquivo (bonus +10B score se season/episode bater)
         -> buildStreamPermalink() -> URL CDN Torbox

   c. Se NAO encontrado:
      -> torboxService.addMagnet(magnet, apiKey)
         -> POST /torrents/createtorrent
         -> extrairMagnetHash() -> await analisarMagnet(magnetLink)
      -> Aguarda download completar

10. Retorna HTTP 302 redirect para URL do CDN Torbox

========================================================================
PONTOS DE VERIFICACAO DE INFOHASH
========================================================================

1. DEDUP: catalogProvider remove torrents com mesmo infoHash
2. NOME CANONICO: filterAndValidateTorrents usa "dn" do magnet no TitleFilter
3. RESOLVER: Torbox verifica se infoHash ja existe na conta do usuario
4. CACHE: RdTorrentCacheService armazena torrentId por magnetHash (30 dias)
5. STREAM CACHE: streamLink cache por torrentId+season+episode (24h)
